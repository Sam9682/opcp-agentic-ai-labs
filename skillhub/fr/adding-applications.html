Ajout de nouvelles applications avec l'IA agentique (Annexe – facultatif)

Débutant ⏱ ~20 min

Apprenez à enregistrer et déployer des applications sur la plateforme AI-Powered-Store en utilisant le CLI, l'API REST et l'interface web d'administration.

Prérequis

  • Terminé : Installation sur Ubuntu Bare-Metal
  • Instance AI-Powered-Store en fonctionnement
  • Accès administrateur à l'interface web

Ce que vous apprendrez

  • Enregistrement d'applications via le CLI (opcp-explorer.py)
  • Enregistrement d'applications via l'API REST
  • Enregistrement d'applications via l'interface web
  • Configuration des métadonnées d'application
  • Gestion des applications existantes (édition, suppression)

Interface de gestion des applications

L'interface web d'administration fournit un tableau complet listant toutes les applications enregistrées sur la plateforme. Accessible via le menu Applications dans la barre de navigation.

Colonnes du tableau

Chaque application enregistrée affiche les informations suivantes :

Colonne Description
ID Identifiant unique de l'application dans la base de données
NAME Nom technique de l'application (ex : ai-shai-web-interface, opcp-agentic-ai-labs)
URL URL publique d'accès à l'application une fois déployée (ex : https://opcp-psmc.com/admin/ai-staticwebsite)
DESCRIPTION Description lisible de l'application (ex : « Interface Web pour Shai », « OPCP Openstack Automation »)
GIT URL URL du dépôt Git source (ex : git@github.com/Sam9682/ai-shai-web-interface.git)
GIT SIZE (MB) Taille du dépôt Git en mégaoctets
BUILD (S) Temps de build en secondes (N/A si non encore construit)
START (S) Temps de démarrage en secondes
STOP (S) Temps d'arrêt en secondes
PS (S) Temps de vérification du statut (process status) en secondes
SWAUTOMORPH URL URL de déploiement Swautomorph (« Not yet deployed » si non déployée)
ACTIONS Boutons Edit et Delete pour gérer l'application

Actions disponibles

  • Add New Application — Bouton en haut à droite pour enregistrer une nouvelle application
  • Download PDF — Exporter la liste des applications au format PDF
  • Edit — Modifier les métadonnées d'une application existante (nom, URL, description, dépôt Git)
  • Delete — Supprimer une application de la plateforme

Méthode 1 : Ajout via l'interface web

C'est la méthode la plus simple pour les administrateurs :

  1. Connectez-vous à l'interface d'administration
  2. Accédez au menu Applications dans la barre de navigation
  3. Cliquez sur le bouton Add New Application
  4. Remplissez le formulaire avec les informations requises :
    • Name : nom technique (sans espaces, en minuscules)
    • Description : description lisible
    • URL : URL publique d'accès
    • Git URL : URL du dépôt source
  5. Validez le formulaire

Méthode 2 : Ajout via le CLI

Le script CLI permet d'enregistrer des applications en ligne de commande :

# Activer l'environnement virtuel
cd ~/opcp-agentic-ai-labs
source .venv/bin/activate

# Enregistrer une nouvelle application
python opcp-explorer.py add-app \
  --name "mon-application" \
  --description "Description de mon application" \
  --git-url "git@github.com/user/mon-application.git" \
  --url "https://mon-domaine.com/admin/mon-application"

Méthode 3 : Ajout via l'API REST

L'API REST permet l'intégration dans des pipelines CI/CD :

# Enregistrer une application via l'API
curl -X POST https://<votre-domaine>/api/applications \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <votre-token>" \
  -d '{
    "name": "mon-application",
    "description": "Description de mon application",
    "git_url": "git@github.com/user/mon-application.git",
    "url": "https://mon-domaine.com/admin/mon-application"
  }'

Modification d'une application existante

Pour modifier les métadonnées d'une application existante :

  1. Localisez l'application dans le tableau
  2. Cliquez sur le bouton Edit dans la colonne ACTIONS
  3. Modifiez les champs souhaités dans le formulaire d'édition
  4. Sauvegardez les modifications

Suppression d'une application

Attention : La suppression d'une application est irréversible. Assurez-vous d'avoir une sauvegarde avant de procéder.
  1. Localisez l'application dans le tableau
  2. Cliquez sur le bouton Delete dans la colonne ACTIONS
  3. Confirmez la suppression dans la boîte de dialogue

Configuration du skill : MODIFY_CODE

L'action de modification de cette page est pilotée par le skill d'agent MODIFY_CODE. Le prompt ci-dessous est la configuration exacte que l'agent suit pour tuer de force (SIGKILL) les conteneurs Docker de l'application et les supprimer tout en préservant les volumes nommés.

Variables d'exécution : les jetons tels que {{APPLICATION_FOLDER}} et {{USER_ID}} sont remplacés par des valeurs concrètes au moment de l'exécution.
Afficher le prompt du skill MODIFY_CODE (SKILL.md) 
---
name: KILL
description: Forcefully kill all running Docker containers of a deployed application instance for a specific user, immediately terminating the processes (SIGKILL) instead of a graceful shutdown, then remove the stopped containers while preserving volumes.
---

# KILL Skill

## Purpose
You are an autonomous Operations agent running on a Linux server with access to
the local filesystem and shell commands.

This skill **forcefully kills** all running Docker containers that belong to a
deployed application instance for a given user. Unlike the `STOP_APP` skill — which
performs a graceful `docker stop` (SIGTERM then timeout) — this skill issues a
`docker kill` (SIGKILL) to terminate the containers **immediately**, then removes
the dead containers. Use it when the application is unresponsive, hung, or must be
torn down right away.

The application source code and its `docker-compose` setup are located in the
git repository:

```
REPO_DIR = "{{APPLICATION_FOLDER}}"
```

IMPORTANT:
- All commands have to be executed in the application located `{{APPLICATION_FOLDER}}`.
- Execute all steps with the environment variable `USER_ID={{USER_ID}}`.
- `docker kill` is **not graceful**: in-flight requests are dropped and the
  application has no chance to flush state. **Named volumes and data are
  preserved** (we never run `docker volume rm`), but any unsaved in-memory state
  is lost. Only use KILL when an immediate termination is required.

## Procedure

### 1. Calculate HTTP Ports

Calculate the HTTP/HTTPS ports used by the Docker containers of the application.
Use the following command:

```bash
source {{APPLICATION_FOLDER}}/conf/deploy.ini
RANGE_START=${RANGE_START:-6000}
RANGE_RESERVED=${RANGE_RESERVED:-100}
RANGE_PORTS_PER_APPLICATION=${RANGE_PORTS_PER_APPLICATION:-12}
if ! [[ "$USER_ID" =~ ^[0-9]+$ ]]; then
    USER_ID=0
fi
PORT_NAMES=(
    HTTPS_PORT HTTP_PORT
    HTTPS_PORT1 HTTP_PORT1
    HTTPS_PORT2 HTTP_PORT2
    HTTPS_PORT3 HTTP_PORT3
    HTTPS_PORT4 HTTP_PORT4
    HTTPS_PORT5 HTTP_PORT5
)
PORT_RANGE_BEGIN=$((RANGE_START + USER_ID * RANGE_RESERVED))
base=$((PORT_RANGE_BEGIN + APPLICATION_IDENTITY_NUMBER * RANGE_PORTS_PER_APPLICATION))
offset=0
for name in "${PORT_NAMES[@]}"; do
    printf -v "$name" '%s' "$((base + offset))"
    export "$name"
    offset=$((offset + 1))
done
```

### 2. Identify the target containers

Find the running containers that belong to this application instance, based on
the naming convention used at deploy time (name pattern
`${NAME_OF_APPLICATION}-.*-${USER_ID}-.*`):

```bash
echo "Identifying {{APPLICATION_NAME}} containers for USER_ID=$USER_ID..."
containers=$(docker ps -q --filter "name=${NAME_OF_APPLICATION}-.*-${USER_ID}-.*")

if [[ -z "$containers" ]]; then
    echo "No running containers found for USER_ID: $USER_ID — nothing to kill."
    exit 0
fi

echo "The following containers will be KILLED (SIGKILL):"
docker ps --filter "name=${NAME_OF_APPLICATION}-.*-${USER_ID}-.*" \
    --format 'table {{.ID}}\t{{.Names}}\t{{.Status}}'
```

### 3. Forcefully kill the containers

Send SIGKILL to every matching container to terminate it immediately, then
remove the dead containers. **Do not** run a graceful `docker stop` first — the
point of this skill is the forced kill.

```bash
echo "Killing {{APPLICATION_NAME}} services (SIGKILL)..."

# Force immediate termination of the processes inside the containers.
docker kill $containers

# Remove the now-dead containers (force in case any lingers).
docker rm -f $containers

echo "Services killed successfully ✅"
```

### 4. Verify and report

After completion, verify the result and report:

```bash
remaining=$(docker ps -q --filter "name=${NAME_OF_APPLICATION}-.*-${USER_ID}-.*")
if [[ -z "$remaining" ]]; then
    echo "✅ All {{APPLICATION_NAME}} containers for USER_ID=$USER_ID are gone."
else
    echo "⚠️  Some containers are still running:"
    docker ps --filter "name=${NAME_OF_APPLICATION}-.*-${USER_ID}-.*" \
        --format 'table {{.ID}}\t{{.Names}}\t{{.Status}}'
fi
```

**After completion, verify:**
- All targeted containers have been killed and removed.
- Named volumes are **preserved** (data is not deleted).
- Any dangling networks created only for this instance may remain and are safe to ignore.

**Summary:** print a short summary including:
- The `USER_ID` and application name targeted.
- The list of containers that were killed (IDs / names).
- The final status (all killed, or any containers still running with the reason).
- Any warnings (e.g. no containers were found, a container could not be removed).

If ANY step fails, explain clearly which step failed and why.
